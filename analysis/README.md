# Independent five-company AI patent analysis

Start with `outputs/analysis_report.md`. The dataset is at
`outputs/clean_patent_company.csv.gz`. It retains all 271,415 original rows and
all 46 original columns, plus derived fields. Read IDs as strings to preserve
application leading zeros. This is a patent-company membership file, not a
distinct-invention-family file. The one cross-company shared patent remains
under both assignees; pooled document tables count it once.

Load the derived dataset without losing leading zeros:

```python
import pandas as pd

data = pd.read_csv(
    'outputs/clean_patent_company.csv.gz',
    dtype={name: 'string' for name in
           ['doc_id', 'patent_id', 'appl_id', 'assignee_id', 'location_id']},
    float_precision='round_trip',
)
```

## Run the analysis

Use Python 3.12 or later and keep the supplied original CSV separately:

```bash
python -m pip install -r requirements.txt
python code/run_pipeline.py --input /path/to/five_big_tech_ai_patents.csv --output outputs
```

The runner is usable from any working directory; pass absolute input/output
paths when appropriate. The audit fails instead of silently deleting or
repairing hard integrity problems. Stages execute sequentially. There is no
random sampling, remote API, trained predictive model or download in the code.
The reference run uses Python 3.12; its exact source SHA-256 and environment
versions are recorded in `outputs/audit.json`. The source CSV is not duplicated
inside this bundle.

The runner checks the original source SHA-256 before writing results because
the report includes findings specific to this extract. The reusable validation,
feature and numerical methods can be adapted to new extracts, but the report
builder must also be updated before analyzing a different source. This guard
prevents accidentally attaching this study's narrative to changed data.

## Files

- `code/01_data_validation.py`: schema, IDs, merge consistency, duplication,
  scores, threshold rules, assignee and time coverage.
- `code/02_cleaning.py`: unchanged source rows/values plus documented features.
- `code/03_eda.py`: trends, profiles, co-occurrence, anomalies and six figures.
- `code/04_statistical_analysis.py`: ten exploratory annual trend tests,
  effect sizes, temporal confidence intervals, Holm correction, diagnostics,
  bounded empirical-logit sensitivity and two figures.
- `code/05_modelling.py`: explicit decision against circular predictive ML.
- `code/06_results.py`: all-source-value and count conservation checks, reports.
- `code/common.py`: transparent numerical HAC implementation and shared I/O.
- `outputs/data_quality_report.md`, `statistical_analysis.md`,
  `research_log.md`, `research_log.jsonl`: substantive documentation.
- `outputs/tables/`: all descriptive, validation, statistical and sensitivity
  results, transformation dictionary and restriction ledger.
- `outputs/figures/`: eight GitHub-friendly SVG figures. PNG versions are generated by the pipeline but are not committed here.
- `outputs/verification.json`: final conservation/provenance checks.

## Interpretation

The main definition is any-AI at score >=0.86, with 0.50 and 0.93 sensitivity.
Scores are model outputs, not verified truth probabilities. Main comparisons
use 2010-2023; recent profiles compare 2021-2023 with 2014-2016. All tests are
post-EDA exploratory, and confidence intervals are conditional temporal model
intervals. Full company coverage, merge recall, invention families, classifier
error and current activity cannot be established from this extract alone.
